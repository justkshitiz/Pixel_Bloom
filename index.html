Guides & Docs

Documentation & Guides

Everything you need to compress, run locally, contribute, and deploy.

1. Using Pixel Bloom ▾

Pixel Bloom optimizes files directly in client memory without transmitting data over the network:

  • Format Selection: Select Image mode (JPEG, PNG, WebP) or PDF document mode.
  • Quality Slider (5%–95%): Dynamically recalculates DCT stream quantization and downsamples raster imagery between 72 DPI (Low) and 300 DPI (High).
  • Target Size Mode: Employs a 6-iteration binary search solver to meet requested byte limits within physical file constraints.
  • Client Guard: Enforces a strict 25 MB safety limit to protect mobile memory runtimes from heap overflow.
  • Zero-Loss Fallback: If a document cannot be compressed without file bloat, original bytes are safely retained with 0% false savings reported.
2. Run Locally ▾

Web Workers and WebAssembly require a local HTTP server origin to circumvent browser security limitations on file:// URLs:

# 1. Clone the repository
git clone https://github.com/justkshitiz/Pixel_Bloom.git
cd Pixel_Bloom

# 2. Start a lightweight static server (Node.js)
npx -y serve . -p 8080

# Or with Python 3:
python3 -m http.server 8080

Open http://127.0.0.1:8080 in any modern browser. To run the automated quality gate:

# Run native unit tests and Playwright browser tests
npm install
npm test
3. Fork & Contribute ▾

A fork creates an independent, isolated copy of Pixel Bloom under your GitHub account for safe testing:

# 1. Fork repository via GitHub UI, then clone your fork:
git clone https://github.com/<your-username>/Pixel_Bloom.git
cd Pixel_Bloom

# 2. Create a dedicated feature branch:
git checkout -b feat/custom-feature

# 3. Test your changes locally:
npm run test:unit

# 4. Commit and push:
git add .
git commit -m "feat: enhance feature description"
git push origin feat/custom-feature

Open a Pull Request on GitHub against the upstream main branch to propose your contribution.

4. Deploy Your Own Copy ▾

Deploy a standalone version to GitHub Pages with continuous testing:

  1. Navigate to Settings → Pages in your GitHub repository.
  2. Under Build and deployment → Source, select GitHub Actions.
  3. Every push to main executes unit checks, runs Playwright Chromium suites, and deploys to https://<username>.github.io/<repo>/.
  4. Pixel Bloom relies entirely on relative asset paths (./hyper-compress/...), guaranteeing zero 404s when hosted under subdirectories.

Privacy-First Architecture

Pixel Bloom operates without external API servers, proxies, or remote storage. All byte manipulations execute locally inside your browser's Web Worker and HTML5 Canvas memory spaces. No telemetry or file metadata is ever transmitted.

Under the Hood

  • PDF Optimization: BentoPDF Hyper Compress engine running compiled C++ PDFium, QPDF object stream recompression, and Jpegli lossy DCT quantization.
  • Image Optimization: Native HTML5 Canvas 2D raster engine handling WebP, JPEG, and PNG conversions with sub-pixel interpolation.
  • Concurrency: ES module Web Worker threads paired with zero-copy transferable ArrayBuffer payloads to prevent UI thread stutter.
